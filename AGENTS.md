# Maintaining One U Education skills

- `skills/<name>/` is the single source of truth for the plugin-side instructions. Keep skill names and the MCP identity stable.
- Put the general workflow in SKILL.md and on-demand detail in `references/`. The direct-install manifests for each client in the repository root are generated by `scripts/platforms.py`: edit the script and regenerate, never edit the manifests by hand. The ChatGPT review package, its review details and the packaging logic belong to oneuedu-plugin.
- The application flow currently relies on secure widgets and a person clicking them. When migrating or adapting a client, never replace widget confirmation with consent given in chat. What can connect, what is authorised and which tools are available depend on what the host and the service actually provide.
- After a change, run `python3 scripts/check.py` and `python3 -m unittest discover -s scripts -p 'test_*.py'`. Business changes also need to be verified against the matching service or client.
- After committing and pushing skill changes, check out the matching submodule commit in the plugin repository and commit the parent repository's Git pointer. The plugin's `plugins/one-u-education/skills` references this whole repository, and packaging takes only its `skills/` folder. Don't copy files across or maintain a per-file lock file, and never release from uncommitted submodule work. This repository contains no server implementation, account credentials or real business records.
- This repository is public. Write the README, docs, commit messages and pull request titles and descriptions in English.
